What we're comparing

Three execution paths

Baseline

Single LLM call

Yes — baseline is exactly one direct LLM query: prompt in, answer out, no routing, no memory, no tool calls, no orchestration. It represents the floor: what you get for free with no infrastructure.

In the live adapter this means a single POST /v1/chat/completions to whichever model is configured, with the question as the user message and nothing else. No system prompt beyond a minimal role statement.

latency~200–800ms
tokens~100–400
routing overheadnone
compliance checknone
endpointPOST /v1/chat/completions
Agent Loop

Elan orchestrator

The agent loop adds Elan's orchestration layer on top of the same LLM. The question is routed through AgentRouter.dispatch/2, which selects a skill, manages tool-call iterations, handles retries, and wraps the response in a structured RunResult.

Unlike the baseline, the agent loop can invoke multiple tool calls in a single answer (e.g. searching, reading context, reflecting). The additional latency and tokens come from those round-trips, not from a heavier model.

latency~800–2500ms
tokens~400–900
routing overheadskill selection
compliance checknone
endpointPOST localhost:4001/run_skill
Stack

Full orchestration stack

The stack runs the question through CSC (compile + laxity check), TokenGov (policy + conflict detection), and Spectral (SLO monitoring) before the Elan agent executes. MetaBus events are emitted at each layer.

This is the most expensive path — but it's also the one with formal governance, IRAP compliance enforcement, confabulum rate tracking, and CoverageOracle monitoring. The extra latency and tokens buy you verifiability and metacognitive feedback.

latency~1200–4000ms
tokens~500–1100
routing overheadCSC → TokenGov → Spectral → Elan
compliance checkIRAP · EU AI Act · SRA
endpointPOST localhost:4003/compile → 4002 → 4001
When does the overhead pay off? The stack adds ~600–1500ms and ~20–30% more tokens over the agent loop. Based on simulated data, that overhead earns back accuracy gains primarily on Tier 3 (Legal) — where compliance checking catches wrong citations and stale regulations — and Tier 5 (Metacog), where CoverageOracle and LaxityProbe enable genuine self-awareness. On Tier 1 (Factual) lookups, the stack adds latency with no accuracy benefit; the bare baseline is often competitive.

How it works

Methodology

Question tiers

  • Tier 1 — Factual (10 q): Short-answer lookups. Shannon entropy, IRAP acronym, Elixir APIs, Schnorr verification. Scored by exact match or Jaccard similarity.
  • Tier 2 — Reasoning (8 q): Multi-step calculation. Laxity severity from threshold breach, UCB1 arm selection, SpeculumFreshness staleness. Scored by semantic overlap.
  • Tier 3 — Legal (6 q): Compliance reasoning. IRAP ISM-0839, EU AI Act Art.13, SRA Principle 6, GDPR Art.44. Scored by legal concept coverage.
  • Tier 4 — Code (6 q): Code generation and review. KL-divergence in Elixir, UCB1 formula, GenServer unique names. Scored by rubric (function names, patterns, correctness indicators).
  • Tier 5 — Metacog (5 q): Self-referential questions about the stack itself — sorry depth SLO status, which module detects drift, Wave 4 audit findings. Scored by semantic similarity to ground truth.

Scoring methods

  • exact_match: Normalise both strings (lowercase, strip punctuation, collapse whitespace), return 1.0 if equal, 0.0 otherwise.
  • semantic (Jaccard): Tokenise both strings into word sets, return |intersection| / |union|. Correlates well with factual recall without requiring embedding calls.
  • rubric: Structured criteria list (e.g. "contains 'sqrt'", "mentions 'UCB'", "defines a function"). Each criterion is a substring or regex check. Score = fraction of criteria met.

Live adapter endpoints

  • localhost:4001 — Elan HTTP (AgentLoop adapter)
  • localhost:4002 — TokenGov (governance check)
  • localhost:4003 — CSC (compile + laxity)
  • localhost:4004 — Recursa (SLO + CoverageOracle)

If services are not running, adapters return {:error, :service_unavailable} and the run records the error without crashing.

π = acc_δ − 0.001 × lat_δ − 0.0001 × tok_δ
acc_δ = stack accuracy − agent loop accuracy lat_δ = stack mean latency − agent loop mean latency (ms) tok_δ = stack mean tokens − agent loop mean tokens

π > 0 → stack wins overall · π < 0 → agent loop wins · weights are tunable in MetricCollector.tradeoff_report/0
